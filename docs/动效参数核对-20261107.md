# 动效参数核对

核对日期：2026-11-07。本次区分当前程序参数、微软通用设计规范、本机系统动画库返回值，以及 Windows 11 托盘面板的私有实现。不能把这些来源当成同一组参数。

## 当前 TrayNest

源码 DismissAnimation.cs 与 TrayPanel.cs：

- 时长160ms，位移24 DIP，无淡入淡出。
- 退出进度为 t^2.4，打开时反向使用该幂函数；不是三次贝塞尔曲线。
- WinForms计时器15ms更新一次窗口位置，依赖主界面线程。
- 自动展开在系统隐藏区窗口刚可见时触发，没有等待原面板动画结束。

因此，当前已有的“系统原生动画参数不可读”测试标记不够准确：公开系统动画库有可读参数，但它不等于任意 Windows 11 Shell 组件的实际配置。

## 本机直接读取的系统预设

独立只读工具使用 Windows.UI.Core.AnimationMetrics.AnimationDescription，effect对应ShowPopup、HidePopup等，target为Primary。没有连接或修改Explorer，也没有运行第三方软件。

| 系统预设 | 属性 | 延迟 | 时长 | 曲线／终值 |
| --- | --- | --- | --- | --- |
| ShowPopup | 位移 | 0ms | 367ms | cubic-bezier(0.1, 0.9, 0.2, 1) |
| ShowPopup | 透明度 | 83ms | 83ms | 线性，0→1 |
| HidePopup | 透明度 | 0ms | 83ms | 线性，→0 |
| ShowPanel | 位移 | 0ms | 550ms | cubic-bezier(0.1, 0.9, 0.2, 1) |
| HidePanel | 位移 | 0ms | 550ms | cubic-bezier(0.1, 0.9, 0.2, 1) |
| PointerDown／PointerUp | 缩放 | 0ms | 167ms | cubic-bezier(0.1, 0.9, 0.2, 1) |

原始数值保存在本地 verification/native-motion/windows-animation-metrics.json，工具源代码同目录。浮点误差已在表中整理为标称控制点。

微软说明：[AnimationMetrics命名空间](https://learn.microsoft.com/en-us/uwp/api/windows.ui.core.animationmetrics)、[TranslationAnimation的时长与控制点](https://learn.microsoft.com/en-us/uwp/api/windows.ui.core.animationmetrics.translationanimation)。该API返回系统动画库的公开预设，并不证明Windows 11托盘一定使用ShowPopup，或没有私有覆盖。

## 微软当前通用规范

官方文档列出的命名时长为ControlFasterAnimationDuration=83ms、ControlFastAnimationDuration=167ms、ControlNormalAnimationDuration=250ms。进入、移位、退出按用途使用不同曲线，不能只换一个时长。[Timing and easing](https://learn.microsoft.com/en-us/windows/apps/design/motion/timing-and-easing)、[Motion in Windows](https://learn.microsoft.com/en-us/windows/apps/design/motion/)。

例如通用规范的Direct Entrance给出cubic-bezier(0,0,0,1)，与上面本机公开Popup库的(0.1,0.9,0.2,1)不是同一条曲线。应按真实目标场景确认来源，不拼成一套所谓唯一原生参数。

## 本机托盘资源核对

已定位本机Taskbar.View.dll，版本2126.8901.10.0，内部保留NotificationAreaOverflow.cpp来源路径。Windows SDK makepri读取了当前resources.pri中的SystemTrayResources.xbf和DinnerTime变体。

字符串表包含NotificationAreaOverflow、OverflowRootGrid、背景材质状态，以及SystemTray_IconRotateDuration。出现的0.3秒和0.083秒字符串没有足够关联证据，不能直接认定为隐藏区打开时长。二进制还引用WindowsUdk.UI.Shell.ShellViewAnimationProperties等私有组件，说明仅查询公开AnimationMetrics不足以断言该托盘面板的最终参数。

本轮没有完整解码并确认托盘打开／关闭动画的私有覆盖，也没有以实际桌面逐帧采样拟合它。该部分仍是明确未知，而不是已经读到的固定值。

## 调整时需要同时处理

1. 为打开和关闭分别设置曲线、位移与透明度，不再简单反转同一幂函数。
2. 上方自动展开应等原面板动画完成并确认锚点后，从相邻边缘出现；不能只以HWND可见作为完成信号。关闭、快速重开和拖动需要取消旧的等待。
3. 分别检查主面板和收纳面板的悬浮高亮，尤其是浅色背景。用户截图指向原生主面板，不能只改自绘收纳面板后称全部解决。
4. 检查帧调度。Windows组合动画通常在独立线程执行；当前WinForms主线程计时器可能受刷新、UIA和拖动工作影响。参考[微软组合动画说明](https://learn.microsoft.com/en-us/windows/apps/develop/composition/composition-animation)。

## preview.13 实施与验证

已将布局测量移到后台，动画前确定锚点，取消打开后定时硬对齐，并用DWM刷新驱动动画更新。快速重开保留当前位移与透明度；真正发生布局变化时平滑移位。

跟随系统隐藏区时，用户可选择“同时”或“先后”。先后模式使用367ms保守入口等待和80ms测量稳定检查，最长等待1200ms后使用估计几何。这是公开Popup预设与稳定性检查的组合，不是读取Shell私有动画完成事件；不同系统或自定义动画可能需要进一步适配。同时、手动及悬停打开不使用这段先后等待。

实桌面回归检查连续轨迹、无结束后硬对齐、帧间隔、快速重开和取消等待。强悬浮高亮仍是独立待办，尚未在本版修改。没有宣称已复刻Windows 11托盘的私有动效。
