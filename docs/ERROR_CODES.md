# 错误编号与反馈

错误编号用于分类，同一类别通常保持相同编号；事件 ID 标识一次具体发生的问题。处理 Issue 时请同时核对程序版本、错误编号、事件 ID 和复现步骤。

| 编号 | 含义 | 建议处理 |
|---|---|---|
| TN0010 | 自启动设置已写入并核验 | 使用当前用户登录任务，核对日志中的 Enabled 状态 |
| TN0011 | Windows 任务栏已就绪 | 随后恢复保存的收纳规则；启动日志中的 LaunchMode 区分登录启动与手动启动 |
| TN0012 | 启动后收纳检查 | 第 5 秒和第 30 秒记录保存数量、实际收纳数量与已发现图标数量；未运行工具保留占位 |
| TN1001 | 系统不支持或任务栏尚未就绪 | 检查 Windows 11 x64，等待任务栏出现后重试 |
| TN1002 | 收纳配置损坏或不可读 | 原文件保持不变；附诊断报告，保留本地配置及备份供本人恢复 |
| TN1003 | 启动失败 | 查看异常类型、HResult、方法调用栈 |
| TN1004 | 等待任务栏超时 | 登录启动最多等待两分钟；任务栏出现后重试并附诊断报告 |
| TN1101 | 未识别的托盘消息格式 | 消息原样交给系统，结合系统版本和报告中的格式计数排查 |
| TN1102 | 系统拖放接口不可用 | 核对运行环境与 HResult，说明拖动时的现象 |
| TN2001 | 原生托盘响应超时，旧版本记录 | 0.2.0-preview.2 及更早会退出；新版用 TN2010 / TN2011 记录自动等待与恢复 |
| TN2002 | 无法维持原图标隐藏 | 工具将尝试退出并恢复，报告是否同时使用其他托盘工具 |
| TN2003 | Explorer 重启 | 工具尝试重新连接；说明是否由用户或其他软件重启资源管理器 |
| TN2004 | 托盘消息处理异常 | 结合版本、方法调用栈和协议计数排查 |
| TN2005 | 自动重启过于频繁 | 五分钟内最多三次；排查后手动重新打开 |
| TN2010 | 原生托盘暂时无响应 | 程序保留运行，按间隔探测恢复，不丢弃收纳配置和顺序 |
| TN2011 | 原生托盘恢复响应 | 自动重新同步原图标和收纳状态，通常无需手动重开 |
| TN2101 | 缺少原图标交互信息 | 刷新图标或重启对应软件；在 Issue 中填写软件名称 |
| TN3001 | 向原软件发送操作失败 | 检查软件是否退出、是否存在权限差异 |
| TN3002 | 收纳或移回失败 | 附操作步骤及报告；写入失败时会尝试回滚 |
| TN4001 | 配置或启动设置写入失败 | 选择可写目录、检查账户权限；原配置通常仍保留 |
| TN4002 | 登录启动任务写入或核验失败 | 附 HResult 和事件 ID；不要只凭注册表中的启动项判断已启用 |
| TN4101 | 保存的工具启动失败 | 右键淡色图标设置有效的 EXE 或快捷方式，或从开始菜单打开；附诊断报告排查 |
| TN4201 | 主面板材质暂时无法同步 | 检查完整包中的 native 组件是否齐全，以及任务栏美化工具是否冲突；原设置会保留，可稍后重试或关闭同步 |
| TN5001 | 导出报告失败 | 选择另一个可写目录，也可以复制报告内容 |
| TN5002 | 剪贴板或打开浏览器失败 | 手动打开项目 Issues 页面 |
| TN6001 | 图标恢复未全部完成 | 恢复清单保留；说明哪些图标仍异常 |
| TN6002 | 恢复保护无法工作 | 不应继续隐藏新图标；附异常类型与 HResult |
| TN6003 | 发现未完成恢复清单 | 保护进程正在恢复，通常随后出现恢复完成记录 |
| TN9001 | 未处理的界面线程异常 | 工具将尝试退出并恢复，复制或导出错误报告 |
| TN9002 | 后台线程致命异常 | 保护进程独立尝试恢复，重新打开后导出报告 |

## 报告内容

- 包含：程序及 .NET 版本、Windows 版本、架构、显示器尺寸、面板 DPI、接口可用状态、图标计数、错误类型、HResult、方法调用栈、有限的近期事件。
- 不收集到导出报告：用户名、设备名称、完整文件路径、图标提示、窗口标题、应用清单、收纳规则内容或截图。
- 异常消息可能带私人文档名或凭据，因此报告仅记录异常类型、错误码与方法名，不包含第三方异常的原始消息和参数。
- 本地日志最多四个文件，每个通常不超过 256 KiB；内存和报告只保留有限近期事件。日志不可写时，当前进程仍尽量保留内存报告。
- “打开 GitHub 反馈”只打开表单，报告由用户检查并提交。没有自动上传或自动创建 Issue。

## 无法保证捕获的情况

断电、系统崩溃、原生进程被强制终止等情况可能来不及记录异常。独立保护进程可以在主进程退出后尝试恢复，但操作系统和来源软件本身也可能影响结果。恢复日志可帮助判断是否执行成功。

## 开机启动排查

0.2.0-preview.4 使用 Windows 任务计划程序，在当前用户登录 10 秒后以交互方式和普通权限启动 `NestedTray.exe --startup`，电池供电和离线均可运行，不设置持续运行时限。启用成功后移除旧的同名 Run 启动项；关闭开机启动会删除此登录任务。任务名以 `TrayNest-Logon-` 开头并带本机用户 SID，每位用户独立。任务名称和完整路径只在本机排查时查看，不包含在公开诊断报告中。

启动日志有 `LaunchMode=Logon` 才能证明此次程序实际经过登录启动入口；任务计划程序中还可以查看上次运行时间和结果。任务运行中显示 `0x41301` 属于正在运行。手动点击任务的“运行”能验证调度到收纳的链路，真实重启登录触发仍需另行验证。程序移动或删除后，应从新位置重新启用开机启动。
